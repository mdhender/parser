# Your first LL(1) Go parser

This tutorial uses `glime`, the separate predictive parser generator. You need
Go 1.27.3 and this checkout, but no C compiler. Start at the repository root.

## Inspect and check the grammar

Open [calc.y](ll1-parser/calc.y). The expression grammar has separate sum,
product, and atom levels, so multiplication binds more tightly than addition.
It uses right-recursive tails instead of left recursion. Each tail returns a
Go function that continues a running total; subtraction therefore remains
left-associative: `19 - 6 - 2` is 11, not 15.

```sh
go build -o /tmp/glime ./cmd/glime
/tmp/glime check docs/tutorials/ll1-parser/calc.y
/tmp/glime explain docs/tutorials/ll1-parser/calc.y
```

The check succeeds silently. The explanation shows which tokens predict each
production, including `$` for end of input and nullable tails. No files are
generated by these two commands.

## Generate and call it

```sh
mkdir -p /tmp/glime-example
/tmp/glime -package main -d /tmp/glime-example generate docs/tutorials/ll1-parser/calc.y
```

Save this caller as `/tmp/glime-example/main.go`:

```go
package main

import "fmt"

func main() {
    result, err := Calc([]CalcToken{
        {Kind: TK_NUM, Value: 19},
        {Kind: TK_MINUS},
        {Kind: TK_NUM, Value: 6},
        {Kind: TK_MINUS},
        {Kind: TK_NUM, Value: 2},
    })
    if err != nil { panic(err) }
    fmt.Printf("Result: %d\n", result)
}
```

Run the generated parser and caller together:

```sh
go run /tmp/glime-example/calc.go /tmp/glime-example/main.go
```

Expected output: `Result: 11`. The generated file has no dependency on this
repository. Do not append an EOF token; finishing the slice signals EOF.

Try `2 + 3 * 7` (23) and `(2 + 3) * 7` (35). Remove a closing parenthesis
to see a useful expected-token error. Semantic actions for completed children
may already have run when a later token fails.

## Recognize an ineligible grammar

The familiar Lemon rule `expr ::= expr PLUS expr.` is left recursive and cannot
be used by glime. `%left PLUS.` does not fix it: glime rejects precedence
directives rather than pretending they resolve LL(1) conflicts. Keep using
`glcc`/`glemon` for LALR grammars, or deliberately restructure your grammar.

For all flags, types, hooks and exclusions, see the
[glime reference](../reference/glime.md). For why completion actions are needed,
see [predictive stacks](../explanation/ll1.md).
